数学建模是什么？What is mathematical modeling?

🎯 本课目标

学完本课(约 15 分钟),你将能够:① 用一句话说清「建模」在干什么;② 以人口预测为例,亲手走通一次完整的建模闭环(假设→建立→求解→检验→修正);③ 说出国赛赛制要点,并知道你的十天冲刺地图在哪。

建模,就是「翻译」

现实问题不会自己长成方程。数学建模(mathematical modeling)做的事是:把现实翻译成数学(方程、规划、统计模型),求解之后,再把数学答案翻译回现实——并对现实说话。

一句话认识国赛:3 人、约 3 天(74 小时)、ABC 三题任选一、交一篇论文。评审盯的是四条:假设的合理性、建模的创造性、结果的正确性、表述的清晰性——注意,没有一条是「模型越高级越好」。

建模闭环:六个环节,一个循环

  1. 明确问题:决策变量是什么?目标是什么?约束是什么?
  2. 模型假设:抓主要矛盾,把次要因素先砍掉,逐条写下你砍了什么。
  3. 模型建立:把假设翻译成方程 / 规划 / 统计结构。
  4. 模型求解:解析解、数值解或编程计算。
  5. 模型检验:拿数据算残差、做灵敏度分析、用常识审问结果。
  6. 应用成文:回答最初的问题,写清楚假设的代价。
检验不达标?回到第 2 步修正假设——闭环的意义就在这里:模型是迭代出来的,不是一次写对的。

走一遍:预测人口(1790 → 2050)

问题:美国自 1790 年起每 10 年一次人口普查。用历史数据建模,预测未来人口。这是最经典的入门案例(Pearl & Reed, 1920),也是国赛 C 题气质的缩影:给数据 → 建模 → 预测 → 检验。

第一轮:指数模型(Malthus, 1798)

假设:单位时间人口的相对增长率为常数 r(出生多、死亡少,净增速率不变)。

dP/dt = rP　⟹　P(t) = P₀·ert

短期看相当准。但指数函数的宿命是爆炸——放到两百年尺度上,它必然脱离现实。怎么发现?靠检验。拖动下面的滑块试试:灰色虚线(指数模型)无论怎么调 r,残差平方和(SSE)都压不下去——这一步叫「检验不达标,回炉假设」。

第二轮:修正假设 → Logistic 模型

哪里错了?「增长率恒定」这个假设。人口越多,资源越紧张,增长率应该随规模递减。最简单的刻画:让增长率线性下降,到容量 K(环境容纳量,carrying capacity)时归零:

dP/dt = rP(1 − P/K)　⟹　P(t) = K / (1 + A·e−rt),A = (K−P₀)/P₀

这就是 Logistic(阻滞增长)模型:S 形曲线,前期近似指数增长,后期被 K 压住。Pearl 与 Reed 用 1790–1910 的数据拟合出 r≈0.031、K≈1.97 亿,预测 1930 年人口 1.231 亿,实际 1.228 亿,误差仅 0.24%——教科书级的成功检验。

但故事没完:20 世纪后期,真实人口越过了 1.97 亿仍在增长。为什么?K 并非常数——农业与医疗技术抬高了容纳量。于是再次回炉假设、改进模型。闭环永远转下去,这正是建模的诚实之处。

⚠️ 常见误区

①「模型越复杂越好」✗ 评审第一条是假设合理性;简单模型 + 完整闭环,胜过大模型黑箱。
②「一次就建对」✗ 检验不达标回炉是常态,论文里写明迭代过程反而加分。
③「拟合得好 = 模型对」✗ 还要外推检验与灵敏度分析——参数微调,结论稳不稳?

🔗 连接你已有的知识

这套闭环你在流体力学里见过:连续介质假设 = 模型假设;N-S 方程 = 模型建立;数值解 = 模型求解;与实验对比 = 模型检验。概统在学的最小二乘,就是今天「检验」环节的数学引擎。

Logistic 的亲戚遍布建环专业:牛顿冷却 dT/dt = −k(T − T室温)(房间温度趋近空调设定值)、传染病 SIR、新产品市场扩散——换壳不换芯。
