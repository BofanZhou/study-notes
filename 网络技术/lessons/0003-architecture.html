网络体系结构 Network Architecture

🎯 本课目标

学完本课(约 15 分钟),你将能够:

① 默写 OSI 七层与 TCP/IP 四层(五层)及各层功能; ② 层—设备—数据单元对号入座(选择题最高频); ③ 说清分层的好处与"协议"三要素。

一、为什么要分层?

两台不同厂商的机器要通信,涉及"用什么线""信号怎么编码""地址怎么编""丢包怎么办"…… 一团麻。分层的答案:把复杂问题切成若干层,每层只做一件事、只对上层提供服务、 只依赖下层。分层的好处(考点):各层相互独立、灵活性好、易于实现维护、 促进标准化、层次解耦。各层的规则集合就是协议(protocol); 计算机网络的体系结构 = 分层 + 各层协议的集合。

协议三要素(背下来):语法(数据格式/结构)、语义(做什么/控制信息含义)、 同步/时序(事件顺序与速度匹配)。

⚠️ 常见误区

"TCP/IP 严格划分了网络接口层"——错,TCP/IP 恰恰没规定底层(这是它灵活的原因)。
"路由器工作在运输层"——错,路由器根据 IP 地址转发,工作在网络层; 根据端口工作的是四层以上的设备(如应用层网关)。
"集线器隔离冲突域"——错,集线器是物理层设备,不隔离冲突域; 交换机的每个端口才是一个独立冲突域。

三、封装:数据是怎么"穿衣服"的

发送方:应用数据 → 加 TCP 头成段 → 加 IP 头成分组 → 加帧头帧尾成帧 → 变比特上线。 接收方逐层"脱衣服"。每一层剥掉/加上自己的头部,靠的就是协议规定的格式—— 这就是协议三要素里"语法"的落地。接收方对等层读对等层写的头部(对等通信原则)。

🔧 工程视角

抓包工具(Wireshark)展示的就是这张图:一个数据包从以太网帧头 → IP 头 → TCP 头 → HTTP 内容, 一层一层展开。综合题"协议分析"和工程排障(看数据包卡在哪一层)用的都是分层模型。 考试里"某功能属于哪一层""某设备工作在哪一层"几乎每卷必考。
