传输层与 TCP Transport Layer

🎯 本课目标

学完本课(约 18 分钟),你将能够:

① 用端口讲清传输层的复用分用,记住常用熟知端口; ② 对比 UDP 与 TCP; ③ 默写三次握手/四次挥手(综合题常客),说出可靠与拥塞控制机制。

一、端口:一台主机上的"房间号"

IP 地址找到主机,靠哪台进程收数据?靠端口(port,16 位 0~65535)。 传输层按端口把数据分给进程 = 分用;多个进程共用一条网络连接 = 复用。 常用熟知端口(必背):FTP 20(数据)/21(控制)、TELNET 23、SMTP 25、DNS 53、 HTTP 80、POP3 110、HTTPS 443;客户端用临时端口(>1024)。

二、UDP vs TCP

对比UDP User Datagram ProtocolTCP Transmission Control Protocol
连接无连接(想发就发)面向连接(三次握手建立)
可靠性尽力而为,可能丢、乱序可靠:不丢、不乱、不重、不漏
首部8 字节(小)20~60 字节
通信方式一对一、一对多、多对一、多对多仅一对一
典型应用DNS、DHCP、视频直播、游戏网页 HTTP、邮件、文件传输

三、TCP 三次握手与四次挥手(必背)

建立连接(三次握手):① 客户端发 SYN=1, seq=x; ② 服务端回 SYN=1, ACK=1, seq=y, ack=x+1; ③ 客户端回 ACK=1, ack=y+1(可携带数据)。

为什么是三次不是两次?防止已失效的连接请求突然又到达——若两次即可建立, 一个滞留的旧 SYN 会让服务端单方面白白建立连接等待资源。三次让双方都确认"双方收发能力都正常"。

释放连接(四次挥手):① 主动方发 FIN;② 对方 ACK(对方还可继续发); ③ 对方数据发完再发 FIN;④ 主动方 ACK,等 2MSL 后关闭 (保证最后的 ACK 能重发、旧报文消亡)。"为什么四次":TCP 全双工,两个方向要分别关闭。

四、可靠传输与流量/拥塞控制

机制一句话
序号 + 确认(ACK)每个字节有编号,ack=n 表示"n−1 前全收到,期待第 n 个"
超时重传计时器到期未收到确认就重发
流量控制 flow control滑动窗口:接收方用rwnd 窗口字段通知"我还能收多少"(点对点,别撑死接收方)
拥塞控制 congestion control慢启动(指数增)→ 拥塞避免(线性加 1)→ 超时回到慢启动/快重传+快恢复;针对网络整体(别挤死路由器)
⚠️ 常见误区

"三次握手中前两次不能携带数据,第三次也不能"——错,第三次握手可以携带数据。
"TIME_WAIT 等一个 MSL 就够"——是 2MSL(ACK 传过去一个 MSL + 对方重发 FIN 再来一个 MSL)。
"UDP 首部 20 字节"——UDP 首部仅 8 字节(源端口/目的端口/长度/校验和 各 2 字节)。

🔧 工程视角

视频会议用 UDP(丢一帧没关系,延迟要小)、网银用 TCP(一个字节都不能错)——工程选型的本质就是 本课的对比表。综合题给一段 TCP 报文序列问"这是第几次握手/哪个字段错了", 按本课的 seq/ack 规则逐项核对即可。
